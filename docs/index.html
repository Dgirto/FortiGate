¿Qué es y para qué sirve?

El conector FortiGate permite que el agente de Ruvic administre un firewall Fortinet FortiGate a través de su REST API v2: puede consultar políticas de firewall, agregar objetos de dirección y revisar logs de tráfico recientes. Una vez configurado, puedes pedirle al agente cosas como:

  • "Lista las políticas de firewall activas en el VDOM raíz."
  • "Agrega un objeto de dirección para la IP 10.0.0.5/32 con el nombre servidor-web."
  • "Muéstrame las últimas 20 entradas del log de tráfico."

Operaciones soportadas:

Operación Qué hace
security.list_policies Lista las políticas de firewall configuradas en el VDOM (solo lectura)
security.add_address_object Agrega un objeto de dirección (IP/subred) real en la configuración del firewall
security.get_logs Consulta logs recientes almacenados en disco (tráfico, eventos, virus, filtro web, IPS)
Qué no hace este conector El conector solo consulta políticas de firewall — no las crea ni modifica. Tampoco administra VPNs, rutas ni interfaces. La única operación de escritura es la creación de objetos de dirección.

Prerrequisitos

  • Un FortiGate (físico o VM) con FortiOS con la REST API habilitada, accesible por HTTPS desde la plataforma Ruvic.
  • Acceso administrativo al FortiGate (rol con permiso para crear perfiles y cuentas de administrador), solo durante la configuración inicial.
  • Acceso de red desde Ruvic al puerto de administración del FortiGate (por defecto 443); regla de firewall local si aplica.
  • La URL base del firewall (ej. https://fw.empresa.com:443) y, si usas VDOMs, el nombre del VDOM a administrar.

Configuración en el fabricante

Vas a crear un perfil de administrador dedicado y de mínimo privilegio, y una cuenta REST API Admin asociada a ese perfil. No reutilices el usuario admin por defecto ni el perfil super_admin.

  1. Crea el perfil de administrador (Admin Profile). En el FortiGate, ve a System → Admin Profiles → Create New. Crea un perfil (ej. ruvic_readonly) y configura el acceso por categoría según la tabla de permisos de la siguiente sección: Read Only en Firewall Policy y Log & Report, Read-Write únicamente en Firewall Address. Deja todo lo demás en None.
    [ Captura: pantalla System → Admin Profiles con el perfil ruvic_readonly configurado — reemplazar por assets/img/fortigate-profile.png ]
  2. Crea la cuenta REST API Admin. Ve a System → Administrators → Create New → REST API Admin. Asigna el perfil creado en el paso anterior (no super_admin) y, si tu política lo permite, restringe la cuenta a las direcciones IP de confianza de la plataforma Ruvic (Trusted Hosts).
  3. Genera el API token. Al guardar la cuenta, FortiOS muestra el token una sola vez. Cópialo de inmediato a un gestor de contraseñas: lo necesitarás en el formulario de Ruvic (campo API Token) y no podrás volver a consultarlo desde la interfaz.
    El token no se puede recuperar Si pierdes el token, deberás regenerarlo (esto invalida el anterior) y actualizar el formulario del conector en Ruvic.
  4. Confirma el VDOM a administrar. Si el FortiGate tiene VDOMs habilitados, anota el nombre del VDOM sobre el que quieres operar (por defecto root). El perfil de administrador y la cuenta REST API deben tener acceso a ese VDOM.
  5. Verifica el token desde fuera del firewall. Desde una máquina con salida de red similar a la de Ruvic, valida que el token responda: 
    curl -k -H "Authorization: Bearer TU_API_TOKEN" \
  "https://fw.empresa.com:443/api/v2/monitor/system/status?vdom=root"
    Si responde con un JSON de estado (código 200), el fabricante quedó listo. Anota estos valores para la siguiente sección: URL base, token, VDOM y si el certificado TLS es autofirmado.

Permisos requeridos

Principio de mínimo privilegio: la cuenta de Ruvic solo necesita estos accesos en el perfil de administrador. No otorgues super_admin ni escritura sobre políticas, VPN o configuración de red.

Permiso (Admin Profile) Para qué lo usa el conector
Firewall Policy — Lectura Consultar políticas de firewall (list_policies). No se otorga escritura: el conector nunca crea ni modifica políticas.
Firewall Address — Lectura-Escritura Crear objetos de dirección nuevos (add_address_object).
Log & Report — Lectura Consultar logs recientes almacenados en disco (get_logs).

Todos los demás accesos del perfil (VPN, Network, System, User & Device, etc.) deben quedar en None. La cuenta debe ser de tipo REST API Admin, no una cuenta de acceso a la GUI/CLI.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Fortinet FortiGate y pulsa Configurar. Diligencia el formulario con los valores obtenidos en la sección de configuración en el fabricante:

Campo del formulario Valor
URL base del FortiGate Ej. https://fw.empresa.com:443, incluyendo el puerto de administración
API Token El token generado al crear la cuenta REST API Admin. Se guarda cifrado como secreto: la interfaz no volverá a mostrarlo
VDOM Opcional; por defecto root
Verificar certificado TLS Actívalo en producción. Desactívalo solo si el firewall usa un certificado autofirmado en un entorno de laboratorio/prueba
Timeout de conexión (segundos) Opcional; por defecto 15 segundos

Guardar y luego pulsa Probar conexión — la plataforma se conectará al FortiGate y confirmará que el token y la red funcionan.

[ Captura: formulario del conector FortiGate en Settings → Conectores — reemplazar por assets/img/fortigate-form.png ]

Verificación

  1. Test de conexión exitoso. El botón Probar conexión ejecuta un ping al estado del sistema del FortiGate y debe responder algo como: "Conexión exitosa a FortiGate (https://fw.empresa.com:443)". La tarjeta del conector cambia a estado Configurado.
  2. Prueba mínima con el agente. Abre una conversación nueva con el agente y pídele:
    "Lista las políticas de firewall de FortiGate."
    El agente debe responder con el listado real de políticas del VDOM configurado. Si lo hace, el conector quedó operativo de punta a punta. Para probar la escritura, puedes además pedirle: "Agrega un objeto de dirección de prueba para la IP 203.0.113.10/32" (el conector pedirá confirmación antes de crearlo).

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Autenticación fallida: Token inválido o sin permiso suficiente para esta operación/VDOM." El API Token es incorrecto, fue regenerado, o el perfil de administrador no tiene acceso al VDOM/categoría solicitada. Revisa el paso de generación del token en la sección de configuración en el fabricante y confirma los permisos de la sección de permisos requeridos.
"Error de red: No se pudo alcanzar el firewall en '...'" La plataforma no alcanza la URL base configurada. Verifica que el host/puerto sean accesibles desde Ruvic (no solo desde tu equipo), que no haya un firewall bloqueando el puerto de administración y que la URL incluya el esquema https:// y el puerto correcto.
Error de certificado TLS / conexión rechazada por SSL El FortiGate usa un certificado autofirmado. En entornos de laboratorio, desactiva "Verificar certificado TLS" en el formulario del conector. En producción, instala un certificado válido en el FortiGate en lugar de desactivar la verificación.
"FortiGate respondió 404/400: ..." al agregar un objeto de dirección Nombre de objeto duplicado o subred con formato inválido. Usa un nombre único en el VDOM y un formato CIDR (10.0.0.0/24) o "IP MÁSCARA".
El conector aparece "Sin configurar" tras guardar Falta la URL base o el API Token (son obligatorios). Ábrelo de nuevo y completa ambos campos; los demás son opcionales.

Preguntas frecuentes y notas de seguridad

¿El agente puede crear o modificar políticas de firewall?

No. El conector solo lee políticas (list_policies); no incluye ninguna operación para crearlas, modificarlas o eliminarlas. La única escritura posible es la creación de objetos de dirección.

¿Dónde queda guardado el API Token?

Como secreto cifrado en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarlo; solo indica "definido". Para cambiarlo, escribe uno nuevo en el formulario; para conservarlo al editar otros campos, deja el campo vacío.

Rotación del token

Recomendado cada 90 días o según tu política: en el FortiGate, ve a System → Administrators, edita la cuenta REST API Admin y regenera el token (esto invalida el anterior de inmediato). Actualiza el nuevo token en el formulario del conector y pulsa Probar conexión.

¿Qué hago si el token se compromete?

  1. Regenera el token de inmediato desde System → Administrators en el FortiGate (invalida el anterior) o deshabilita la cuenta REST API Admin.
  2. Revisa la actividad reciente de esa cuenta en los logs de eventos del FortiGate (Log & Report → Events → System Events).
  3. Actualiza el nuevo token en el formulario del conector en Ruvic.

¿Por qué no usar el usuario admin por defecto?

Porque tendría acceso total al firewall (VPN, rutas, interfaces, otros administradores), muy por encima de lo que el conector necesita. Un perfil dedicado y de mínimo privilegio limita el daño posible si el token se filtra, y permite auditar la actividad del agente por separado del resto de administradores.

¿Qué pasa si el FortiGate no tiene disco local para logs?

get_logs consulta el almacenamiento en disco del FortiGate. Si el firewall no tiene disco local o usa FortiAnalyzer como almacenamiento exclusivo, la operación puede retornar resultados vacíos aunque la conexión funcione correctamente.

Buenas prácticas Usa siempre una cuenta REST API Admin dedicada con un perfil de mínimo privilegio (nunca super_admin); restringe la cuenta a hosts de confianza si tu versión de FortiOS lo permite; desactiva la verificación TLS solo en laboratorio, nunca en producción; y evita compartir el API Token por canales no seguros.
